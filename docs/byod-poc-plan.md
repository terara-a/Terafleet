# BYOD 仕事用プロファイル PoC の当面の計画

## 目的と前提

個人所有の Android 端末に、初期化せずに仕事用プロファイルを追加する。Android Management API と Google の Android Device Policy を使用し、管理側を TypeScript / Cloudflare Workers で実装する。個人用アプリ・写真・アカウントの保持を実機検証の条件とする。

この文書は汎用の計画であり、特定の利用者・端末の情報は記録しない。機種名、OS の実測値、端末名、シリアル番号、IMEI、実際の Enterprise / Device ID、登録 QR コード、画面キャプチャなどは Git・PR・テストデータに含めない。実機情報が必要な場合はアクセス制限された実行環境で扱う。

## 実機登録前の確認

- 最新の Google の利用資格・API 利用条件と BYOD 登録フローを確認する。
- 対象端末が Google Play と仕事用プロファイルに対応していることを確認する。OS / メーカー独自仕様の確認結果は Git に保存しない。
- 既存の仕事用プロファイルや他の MDM 管理がある場合は、削除せずに手順を再検討する。
- 個人データのバックアップを確認する。初期化を要求された場合は登録を中止し、会社所有端末向けの方式へ切り替えない。
- 非準拠時の自動ブロック・削除など、Google の既定動作も確認してからポリシーを決める。

## 管理範囲の制約

- BYOD の仕事用プロファイルに限定する。Device Owner 設定、初期設定画面からの会社所有端末登録、ADB を使う登録は行わない。
- 登録トークンは `allowPersonalUsage: PERSONAL_USAGE_ALLOWED`、短い有効期限、一度だけ使用可能、固定の PoC 用ポリシーを基本とする。
- 登録後は Google の端末情報で個人所有（`PERSONALLY_OWNED`）かつ Profile Owner（`PROFILE_OWNER`）であることを確認し、想定外の所有・管理モードなら変更操作を停止する。
- 端末全体の初期化、ワイプ、端末削除、任意のコマンド実行・Google API 中継は初期 PoC に実装しない。
- 初期ポリシーにはパスワードや端末全体への制限を追加しない。アプリ配布など仕事用領域で検証する操作から始める。
- 個人領域のデータを収集しない。仕事用プロファイルを端末設定から削除する終了手順では、仕事用データが削除されることを明示する。

## 構成

管理者 → Cloudflare Access → 管理画面 / Workers API → Google OAuth → Android Management API → 仕事用プロファイル。

- 管理画面は管理者本人に限定し、Workers 側でも Access JWT を検証する。
- Google の認証情報はサーバー側だけで扱い、必要な値は Workers Secrets に保存する。アクセストークンや登録トークンをログに記録しない。
- D1 に必要最小限の端末対応情報と操作履歴を保存する段階を設ける。実データをリポジトリにエクスポートしない。
- Android アプリや独自 DPC、Python のランタイムは作成しない。

## 実装順序と完了条件

| 段階 | 内容 | 完了条件 |
| --- | --- | --- |
| 1 | Google OAuth と読み取り専用 API クライアント | JWT 署名・期限更新・機密情報保護・Enterprise 一覧のモックテスト、型チェックが成功する。実接続は認証設定後に別途確認する |
| 2 | 管理者認証、Enterprise 登録、最小ポリシー | 保護された管理画面で準備でき、未認証リクエストを拒否する |
| 3 | BYOD 登録、端末一覧、管理モード確認 | 登録トークンを安全に発行し、想定外の管理モードでは変更操作を拒否する |
| 4 | 仕事用アプリの配布と適用状況表示 | 個人領域を維持した実機検証と終了手順を完了する |

実機確認は、仕事用プロファイル作成 → 端末と適用状態の表示 → 検証アプリの公開・インストール → ポリシー一項目の変更 → 個人領域保持の確認、の順で行う。実機登録・ポリシー変更・公開は、それぞれ対象と影響を確認してから実行する。

## 現在の進捗

段階 1 の内部モジュールとネットワークをモックしたテストを追加した。公開 HTTP ルートへの接続、Google の実認証、Enterprise 作成、実機操作、Cloudflare へのデプロイは未実施。認証・管理 API の準備ができるまで、検証用 Worker の用途は変えない。
